# В Telegram

Android-приложение для пересылки входящих SMS и уведомлений выбранного приложения в чат через собственного Telegram-бота. Отдельный сервер не нужен.

```text
SMS → фильтр отправителя и текста ─┐
                                  ├→ зашифрованная очередь → Telegram-бот → чат
Уведомление банка → фильтр текста ─┘
```

## Установка

Скачай APK из [последнего релиза](https://github.com/korenskoy/MyIftt/releases/latest) и установи на Android 8 или новее. Для обновления устанавливай новый APK поверх предыдущего: так сохраняются настройки, очередь и журнал.

Официальные обновления подписаны ключом автора. Сборку с другим ключом Android может отклонить. Не удаляй рабочее приложение ради установки такой сборки: удаление уничтожит его локальные данные.

## Первая настройка

1. Открой приложение **В Telegram**. Пересылка изначально выключена.
2. Введи токен собственного бота из BotFather. Не публикуй токен и не вставляй его в команды терминала.
3. Добавь бота в нужную группу. Разреши боту отправлять сообщения.
4. Отправь в группе команду `/start@имя_бота`. Нажми **Найти чат** и выбери группу.
5. Если бот уже обслуживается другим сервисом, введи ID чата вручную. Приложение не отключает существующее подключение.
6. Нажми кнопку тестовой отправки. Она отправляет одно проверочное сообщение по явному нажатию.
7. Выбери приложение банка или другое приложение, уведомления которого нужно пересылать. Замени примерные текстовые условия своими.
8. Настрой SMS. Поле отправителя задаёт точное совпадение. Текстовые условия ищутся в отправителе или тексте без учёта регистра. Отправитель и текстовые условия применяются вместе. Пустой отправитель и все пустые строки условий отключают SMS.
9. Выдай доступ к SMS и уведомлениям отдельными кнопками. Для банка оставь системный доступ к уведомлениям включённым.
10. Включи пересылку и сохрани настройки.

Приложение читает только новые SMS. Фильтр банка проверяет заголовок и текст уведомления выбранного пакета. Пустой банковский фильтр пропускает все его уведомления. История SMS и контакты не запрашиваются.

## Условия пересылки

У каждого источника есть отдельный список текстовых условий. Достаточно одного совпадения — условия соединяются через **ИЛИ**. Регистр букв не влияет на результат. Пробелы в начале и конце строки не учитываются. Пустые строки не создают условие.

```text
Выбранное приложение банка
             И
  содержит «RUR» ИЛИ содержит «покупка»
             ↓
       Telegram-группа
```

Нажми **Добавить условие**, чтобы указать ещё одну фразу. Удали лишнюю строку кнопкой рядом с ней. Настройки применяются после сохранения. Прежние фильтры, токен и чат сохраняются при обновлении приложения.

Для SMS можно дополнительно задать точного отправителя. Тогда SMS должно прийти от этого отправителя и соответствовать хотя бы одному текстовому условию. При пустом списке текстов достаточно совпадения отправителя.

## Журнал событий

Кнопка журнала открывает последние **100 событий**, новые сверху. Запись содержит время, источник, результат, причину и короткий фрагмент сообщения. В журнал попадают решения по новым SMS и уведомлениям выбранного банка при включённой пересылке, а также результаты отправки в Telegram. Уведомления других приложений не записываются.

Один входящий текст может создать несколько событий: постановка в очередь, временная ошибка, успешная отправка. Старые записи удаляются автоматически. История начинается после установки приложения; прошлые сообщения не импортируются.

Журнал зашифрован на телефоне. Кнопка очистки удаляет только журнал, после подтверждения. Очередь отправки и настройки сохраняются. Журнал обновляется при открытии и по кнопке; постоянного опроса нет.

## Отправка и восстановление

- Сообщение содержит источник, текст и время события. Ссылочные предпросмотры выключены.
- Очередь переживает закрытие приложения, потерю сети и перезагрузку телефона. После принудительной остановки Android открой приложение снова.
- Повторные обновления одинакового банковского уведомления отсекаются. Новые отдельные SMS с одинаковым текстом сохраняются.
- Временные ошибки повторяются с задержкой. Ограничение частоты Telegram учитывается. Постоянные ошибки видны в статусе; исправь настройки и сохрани их снова.
- Отключение пересылки приостанавливает очередь. Тестовая отправка работает и при выключенной пересылке.
- Очередь сохраняет первоначальный ID чата. Изменение чата действует на новые события. Для удаления старых сообщений используй кнопку удаления очереди с подтверждением. Уже отправленный запрос может успеть доставить сообщение.
- Токен, очередь и журнал зашифрованы ключом Android Keystore. Резервное копирование и перенос данных отключены. Удаление приложения удалит настройки, очередь и журнал.

## Данные и разрешения

Токен бота вводится после установки в самом приложении. Он зашифрован ключом Android Keystore. ID чата и условия сохраняются локально в настройках. Содержимое подходящих сообщений отправляется в выбранный Telegram-чат, где доступно его участникам.

Приложению нужны разрешения на входящие SMS, сеть и восстановление очереди после перезагрузки. Доступ к уведомлениям пользователь включает отдельно в настройках Android. Система предоставляет доступ к уведомлениям приложений; форвардер обрабатывает только выбранное приложение. История SMS, контакты, камера и микрофон не запрашиваются.

Файл `.env` для работы Android-приложения не используется и в APK не включается. Перенос секрета в `.env` перед сборкой не скрывает его, если значение затем попадает в APK. Не добавляй токен в исходники, ресурсы или настройки сборки.

## Ограничения

Android и настройки энергосбережения производителя могут задерживать фоновую отправку в режиме сна. Мгновенная доставка не гарантируется. На телефоне можно разрешить приложению фоновую работу, если возникнут задержки.

Android может скрывать чувствительные уведомления и SMS с одноразовыми кодами. Приложение не обходит системные ограничения. После настройки проверь реальное SMS и уведомление выбранного приложения, в том числе при заблокированном экране.

Telegram не предоставляет ключ для устранения повторов `sendMessage`. Если сервер принял сообщение, но ответ потерялся, повторная попытка может создать дубликат. Интерфейс не обещает доставку ровно один раз.

Уведомление, которое банк обновляет с прежними временем и содержимым, может считаться повтором. При обнаружении такого поведения потребуется настройка под фактический формат BL-Online.

## Разработка и проверки

Нужны JDK 21, Android SDK Platform 37 и Build Tools 36 или новее. Укажи путь к SDK в `local.properties` либо через `ANDROID_HOME`. Проверенная сборка использует Gradle 9.6.1 и Android Gradle Plugin 9.3.2.

```sh
./tools/check-core.sh
./gradlew assembleDebug lintDebug assembleDebugAndroidTest
```

APK: `app/build/outputs/apk/debug/app-debug.apk`.

Debug-сборку и её тесты устанавливай только на отдельное устройство для разработки. Для установленной production-версии используй подписанные обновления из `dist/`. Не удаляй production-приложение ради установки debug-сборки: это удалит настройки и зашифрованные данные.

Установка на устройство для разработки:

```sh
adb install -r app/build/outputs/apk/debug/app-debug.apk
adb shell am start -n dev.myiftt.forwarder/.MainActivity
```

Проверка разбора ответов Telegram, очереди и журнала на настоящем Android, без токена и сетевых запросов:

```sh
adb install -r app/build/outputs/apk/androidTest/debug/app-debug-androidTest.apk
adb shell am instrument -w dev.myiftt.forwarder.test/dev.myiftt.forwarder.SetupInstrumentation
```

## Сборка без отладки

Версия `0.2.1` собирается с отключённой отладкой. Подпись выполняется отдельно от Gradle: закрытый ключ и пароли не входят в исходники и APK.

```sh
./gradlew assembleRelease lintRelease
```

Неподписанный файл: `app/build/outputs/apk/release/app-release-unsigned.apk`. Его нельзя устанавливать до подписи. Подписанный файл этой версии: `dist/myiftt-0.2.1.apk`.

Для совместимости с ранними тестовыми установками официальный релиз использует цепочку смены тестового ключа на production-ключ. Android 9 и новее поддерживает такую смену подписи без удаления данных приложения. Старый сертификат остаётся в цепочке доверия; сам release-APK не допускает отладку.

Следующая команда предназначена для автора релиза, у которого уже есть оба ключа и цепочка. Эти закрытые файлы не входят в репозиторий. Для подписи используется `apksigner` из Android SDK Build Tools:

```sh
mkdir -p dist
apksigner sign \
  --ks "$HOME/.android/debug.keystore" \
  --ks-key-alias androiddebugkey \
  --ks-pass file:.signing/debug-pass.txt \
  --next-signer \
  --ks .signing/myiftt-release.p12 \
  --ks-key-alias myiftt \
  --ks-pass file:.signing/store-pass.txt \
  --lineage .signing/signing-lineage \
  --rotation-min-sdk-version 28 \
  --debuggable-apk-permitted false \
  --v4-signing-enabled false \
  --out dist/myiftt-0.2.1.apk \
  app/build/outputs/apk/release/app-release-unsigned.apk
apksigner verify --verbose --print-certs dist/myiftt-0.2.1.apk
```

Эта команда использует новый ключ на Android 9 и новее. Старый ключ подписывает совместимые блоки для Android 8, поэтому он также нужен при повторной подписи такого APK.

```sh
adb install -r dist/myiftt-0.2.1.apk
adb shell am start -n dev.myiftt.forwarder/.MainActivity
```

Сохраняй резервную копию этих файлов вне проекта:

- `.signing/myiftt-release.p12` — закрытый production-ключ;
- `.signing/store-pass.txt` — пароль ключа;
- `.signing/signing-lineage` — цепочка смены ключа;
- `$HOME/.android/debug.keystore` — прежний тестовый ключ для совместимых блоков подписи;
- `.signing/debug-pass.txt` — пароль прежнего ключа.

Каталоги `.signing/` и `dist/` исключены из Git. Не публикуй ключ и пароль вместе с APK. Потеря ключа может лишить возможности выпускать обновления без удаления приложения.

Отключение отладки не гарантирует, что антивирус перестанет обнаруживать приложение. Его вердикт проверяется отдельно.
